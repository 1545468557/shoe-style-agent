# 阶段 3 · 第 2 子阶段 技术开发文档

**日期**：2026-09-21　**项目**：鞋服智能设计 Agent（款式工场）
**子阶段主题**：企划解析结果**可人工修改**（AI 理解错了，用户能当场改）

---

## 一、本子阶段做什么（3 件）

1. **按钮文案**：「解析企划」→ **「开始理解」**（其余按钮不动）
2. **解析结果可编辑**：把只读的"我理解到的"四类字段改成**可编辑输入框**
   - 品类（单行文本）
   - 风格关键词（**一行逗号分隔**，可增删）
   - 人群（单行文本）
   - 价格带（单行文本，例如 `400-600元`）
   - 另加一行 **「补充未提供项」**：把"你没说：…"里的项补上后，该项从清单里移除
3. **保存与标记**：改完点 **「保存修改」** → 界面显示 **「已人工修改」** 标记（明确区分"模型说的"与"人改的"）

## 二、本子阶段**不**做什么（防蔓延）

- 不改模型的解析能力，**不新增任何模型调用**（零费用、零耗时）
- 不做"重新解析并对比差异"、不做修改历史记录
- 不做多轮对话式改写企划
- 不动五道门、不动面料/版型/用料/打样任何逻辑

## 三、接口设计（只加 1 个写接口）

### `POST /api/project/{project_id}/brief/fields`

**请求**（`content-type: application/json`，字段均可选，只传要改的）

```json
{
  "category": "连衣裙",
  "style_keywords": ["度假风", "显瘦", "不易皱", "上镜"],
  "target_user": "25-35岁都市女性",
  "price_band": "400-600元",
  "filled_missing": ["面料成分", "裙长"]
}
```

**响应 200**

```json
{
  "brief": { "text": "…", "parsed": { "...": "合并后的完整对象" } },
  "edited": true,
  "message": "已保存你的修改（未经模型重新解析）"
}
```

**错误**（统一结构 `{"error":{"code","message"}}`，不泄露堆栈）

| code | HTTP | 触发条件 | 人话提示（前端显示） |
| --- | --- | --- | --- |
| `gate_not_confirmed` | 409 | 企划门**已确认**后再改（审计要求：确认后锁定） | 企划已确认，不能再改。如需修改请点「重新编辑」 |
| `invalid_request` | 409 | 字段为空 / 类型不对 / 风格关键词超过 12 个 | 请检查填写内容 |
| `brief_not_found` | 409 | 还没解析就提交修改 | 请先点「开始理解」 |

**校验规则**：`style_keywords` 去重、去空白、最多 12 个、每个 ≤ 20 字；其余字段 ≤ 60 字；全部做 `.strip()`。
**门与审计行为**：`gates.brief == true` 时**一律拒绝写入**（不"悄悄改"）；门退回未确认由前端的 **「重新编辑」** 显式触发（调用既有 `gate` 接口的撤回逻辑，如需新增撤回接口则只允许 brief 门且记审计）。

## 四、前端交互（`app/page.tsx`）

```
我理解到的                    [已人工修改]
品类      [ 连衣裙            ]   ← 可编辑
风格      [ 度假风, 显瘦, 不易皱, 上镜 ]   ← 一行逗号分隔，可增删
人群      [ 25-35岁都市女性   ]
价格带    [ 400-600元         ]
你没说：具体面料成分、裙长、版型细节…     每项右侧一个「补充」按钮 → 填进上面输入框并从清单移除
                        [ 保存修改 ]   [ 确认，开始出效果图 ]
```

- 未确认：输入框可编辑，随时保存、随时确认
- 已确认：输入框 `readonly` 置灰，上方显示「企划已确认（已锁定）」+ 一个 **「重新编辑」** 按钮
- 保存失败（409）时把后端 `message` 直接显示成人话，不显示堆栈

## 五、测试计划（mock，不花模型钱）

## 六、费用与外部依赖

**零新增费用**（无模型调用、无出图）；**无新增外部平台**；**不新增数据上传**；数据仍只落本地 SQLite。

## 七、风险与兜底

| 风险 | 兜底 |
| --- | --- |
| 用户改成空值导致后续流程异常 | 后端校验非空；前端在空值时禁用「保存修改」 |
| 风格关键词格式乱（分号/顿号） | 前端同时支持逗号/顿号/分号切分，统一成逗号存储 |
| 确认后误以为能改 | 锁定态显示原因文案 + 提供「重新编辑」入口 |

## 八、验收标准（照着点）

1. 点 **「开始理解」** → 出现"我理解到的"，四类字段都是**可编辑输入框**
2. 把"品类"改成「半身裙」、风格改成「度假风, 极简」→ 点 **「保存修改」** → 显示 **「已人工修改」**
3. 点 **「确认，开始出效果图」** → 企划门变 ✓，且字段变**只读**
4. 此时直接调接口改字段 → **409 `gate_not_confirmed`**（绕过前端也拒）
5. 点 **「重新编辑」** → 企划门退回未确认，可再改再确认
6. 后端 `python -m pytest` 全过；前端 `npm test`、`tsc --noEmit`、`npm run build` 通过

## 九、给产品经理的三个确认点

1. **做什么/不做什么**：按钮换字 + 四类字段可编辑 + 未提供项可补 + 确认后锁定；**不做**重新解析、不记录修改历史、不动其他流程
2. **有没有新增费用/外部平台/数据上传**：**都没有**
3. **会不会影响本阶段验收**：不影响五道门强制逻辑；只新增一个"确认前可改"的入口，演示时多一句可讲（"AI 理解错了你能当场改"）
