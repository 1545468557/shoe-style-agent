## 一、阶段目标

### 1.1 一句话

**能在演示现场，从一份企划走到"可打样的设计方案"**：企划 → 3 个风格方向（每个方向 1 张效果图）→ 选 1 个（人工门）
→ 选面料（人工门）→ 选版型/工艺（人工门）→ 出 BOM 与尺寸表 → 打样审批（人工门）。
**五道人工确认全部由代码强制**，任何一道没过都不许进入下一步。

### 1.2 交付范围（子阶段 2-1 ~ 2-5，按 9 天切）

| 子阶段 | 名字 | 能做什么 | 不包含 |
| --- | --- | --- | --- |
| **2-1** | 骨架 + 示例库 | 建库、Alembic 迁移、五道门状态机、示例库（面料/辅料/版型/工艺/尺码）导入、企划录入与解析 | 出图、导出 |
| **2-2** | 主链路前半（含出图） | 企划 → **3 个风格方向**（每个方向：名称/灵感/配色/廓形 + **1 张效果图**）→ **门1 门2**：确认企划、确认方向 | 变体批量出图（原计划每方向 3 张 → 砍成 1 张） |
| **2-3** | 主链路后半 | 按方向推荐面料（**门3**）→ 版型/工艺（**门4**）→ BOM + 尺寸表（Excel）→ 打样审批（**门5**，仿真状态机） | 真实打样系统对接 |
| **2-4** | 最小验收界面 + 导出 | 后端自带单页（`static/`）：能点完五道门、看效果图、下载 Word/Excel；SSE 显示进度 | 正式前端工作台（阶段 3） |
| **2-5** | 收口 | 真实模型 + 真实出图各 1 次冒烟；**5–10 条样例打分**校准 D2/D3；演示脚本；README | 上线部署（阶段 4） |

**依赖顺序**：2-1 → 2-2 → 2-3 →（2-4 可与 2-3 并行）→ 2-5。

1. 代码：`projects/鞋服agent开发文档/`（后端 + `static/` 验收页 + `tests/` + `scripts/` + `data/seed/`）。

### 1.4 验收标准

| 编号 | 标准 | 怎么验 |
| --- | --- | --- |
| S1 | 五道门**真的挡住**：任一道未确认时，下一步按钮禁用且写明原因；**直接调接口也拒** | 自动化 + 人工点 |
| S2 | 企划解析给出：品类/风格关键词/目标人群/价格带/成本上限（缺什么就写"未提供"） | 人工点 |

| S9 | 界面**没有任何"真实面料/真实工厂数据"的表述** | 全工程搜索 + 人工看 |
| S10 | 模型输出**结构校验**通过；非法结构走有限重试，失败**不当成功** | 自动化 |
| S11 | 密钥不进代码/仓库/前端产物/日志 | 扫描 |
| S12 | 类型检查 / lint / 测试全过；1440 与 390 宽不横向溢出 | 命令行 + 截图 |

### 1.5 明确不做（9 天内一律不碰）

- **不做**变体批量出图（每方向只 1 张）、相似度查重、多项目并行、3D 试穿、鞋品类。
- **不做**PDF 导出（先 Word + Excel）、正式前端工作台（阶段 3）、真实打样系统对接。
- **不做**账号体系（内部演示用单一工作台；上线前再按底线 7 补登录与数据隔离）。
- **不接**真实 PLM/ERP/物料库（无数据；只**预留**"接真库"的接口形状，并在界面标注示例库）。
- **不改**PRD 里已定的五道人工确认顺序与不可绕过性。

## 二、技术适配摘要

- 采用《技术适配声明》结论：Python 3.12 + FastAPI + Pydantic + pytest；**纵向切片**（人工确认与看图是核心体验）。
- 启用按需模块：SQLite + SQLAlchemy + Alembic、SSE、本地图片目录、python-docx/openpyxl。
- 暂缓：Chroma、对象存储、PostgreSQL、OCR、任务队列（理由见声明 §4）。
- 阶段 2 界面：后端 `static/` 单页（原生 JS + SSE），**不作为正式前端**。

## 三、技术栈与模型

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 文本模型 | **DeepSeek `deepseek-chat`**（OpenAI 兼容接口） | 便宜、够用；比赛/示例企划可用。**放公司未上市款资料前必须换厂商**（D4） |
| 出图 | **云端出图 API**（首选"即梦 / 可灵"其一），抽象成 `ImageProvider` 接口 | 按张计费；**≤¥200/月**；另提供 `placeholder` provider 作为**现场兜底开关**（切了会在界面明示"占位图"） |
| 结构化输出 | Pydantic 模型 + JSON Schema 校验 + 有限重试（≤2 次） | 见 §八 |
| 数据库 | SQLite（`data/app.sqlite3`）+ SQLAlchemy + Alembic | 迁移脚本入库 |
| 进度推送 | SSE（`text/event-stream`），**以 `done` / `error` 收尾** | 出图是长耗时：先提交、进度走 SSE，失败可重试 |
| 导出 | Excel：openpyxl；Word：python-docx | PDF 暂缓 |

## 六、数据、资产与状态

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `project` | id, name, category(默认"连衣裙"), status, created_at | 一个项目 = 一次设计任务 |
| `brief` | project_id, raw_text, parsed(json), confirmed_at | 企划原文 + 解析结果 + **门1** 确认时间 |
| `style_direction` | project_id, seq(1-3), name, inspiration, palette(json), silhouette, image_path, image_status | **门2** 选中哪条（`selected` 标记） |
| `material_pick` | project_id, direction_id, material_id, note, confirmed_at | 引用示例库；**门3** |
| `pattern_pick` | project_id, pattern_id, crafts(json), confirmed_at | **门4** |
| `bom_item` / `size_spec` | project_id, 明细字段 | 导出 Excel 的数据源 |
| `sampling` | project_id, state(草稿→审批→已推送→打样中→评审), note, updated_at | **门5** 的仿真状态机 |
| `run` | id, project_id, kind, status, error_code | 长任务记录（可恢复） |

- **资产**：`data/assets/<project_id>/<direction_seq>.png`，写入用"临时文件 + rename"（原子）。
- **状态机**：项目主状态 `草稿 → 企划已确认 → 方向已选 → 面料已定 → 版型已定 → 待打样 → 打样中 → 评审完成`；五道门分别只允许从对应状态向前一步。

## 七、API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/project` | 新建项目 |
| POST | `/api/project/{id}/brief` | 提交企划原文 → 触发解析（SSE 进度） |
| POST | `/api/project/{id}/gate/brief` | **门1** 确认企划（`{"confirmed": true, "edits": {...}}`） |
| POST | `/api/project/{id}/directions` | 生成 3 个风格方向（长任务，SSE：`phase` / `image` / `done`） |
| POST | `/api/project/{id}/gate/direction` | **门2** 选定方向（`{"direction_id": 2}`） |
| GET | `/api/project/{id}/materials?direction_id=` | 面料推荐（**来自示例库**，带 `is_sample: true`） |
| POST | `/api/project/{id}/gate/material` | **门3** |
| POST | `/api/project/{id}/gate/pattern` | **门4** |
| POST | `/api/project/{id}/sampling` | 提交打样（进入仿真状态机） |
| POST | `/api/project/{id}/gate/sampling` | **门5** 审批 |
| POST | `/api/project/{id}/export` | 导出 Word + Excel（返回文件名） |
| GET | `/api/project/{id}/state` | 全量快照（刷新/重启后恢复） |
| GET | `/api/events/{run_id}` | SSE 事件流 |

**五道门的统一契约**：任何"下一步"接口在门未确认时返回 **409 `gate_not_confirmed`**（含 `gate` 名与一句人话原因）；
界面据此禁用按钮并显示原因。**权限判断在后端**，前端隐藏按钮不算。

**SSE 事件**：`meta` → `phase`（阶段名/进度）→ `image`（出图进行中/完成，带 `image_path`）→ `error`（可重试）→ `done`。

## 八、Prompt 与结构化输出

| 步骤 | 模型要产出 | 校验 |
| --- | --- | --- |
| 企划解析 | `{category, style_keywords[], target_user, price_band, cost_ceiling, missing[]}` | Pydantic；缺项进 `missing`（**不编**） |
| 3 个风格方向 | `[{seq, name, inspiration, palette[{name,hex}], silhouette, image_prompt}]` | 恰好 3 条；`image_prompt` 必须**不含品牌名/商标**（避免侵权） |
| 面料推荐 | 从示例库**候选里选**并排序（禁止生成库里不存在的面料） | 校验 `material_id` 必须存在于库中 |
| 版型/工艺 | 从库里选 + 说明理由 | 同上 |
| BOM/尺寸表 | 结构化明细（不生成价格结论，只汇总库里价格区间） | 数值范围校验 |

**出图**：`image_prompt` = 方向描述 + 品类 + 视角 + 材质关键词 + 约束（无品牌 logo、无人脸特写、白底/模特二选一）。
生成失败 → 该方向标 `image_status=failed` 并可**单独重试**；**不静默换占位图**（除非用户手动切了兜底开关，且界面明示）。

## 九、验收界面（最小，非正式前端）

单页 `static/index.html`：
- 左栏：项目列表 + 五道门进度（当前该点哪个按钮）；
- 中栏：当前步骤的卡片（企划解析结果 / 3 个方向卡片，每个带效果图与"选它"按钮 / 面料表格 / 版型 / BOM 与尺寸表）；
- 右栏：SSE 实时进度 + 错误与重试；
- 顶部常驻：**"示例库 · 数据为仿真实例"** 标识 + 免责声明；
- 底部：导出 Word / Excel 按钮（未就绪时禁用并写明原因）。

## 十、测试要求

**第一层 mock（不花钱，必须全过）**
- 企划解析：正常 / 缺字段 / 模型返回非法结构（重试后仍非法 → 失败，不当成功）—— 8 条
- 方向生成：恰好 3 条校验、`image_prompt` 含品牌名时被拦、出图 mock 成功/失败/重试 —— 10 条
- **五道门（重点）**：每道门"未确认时下一步 409、确认后可前进、跳步被拒、重复确认幂等、前端绕过后端仍拒" —— 5×3=15 条
- 面料/版型：只能从示例库选（生成库里不存在的 id 被拒）—— 6 条
- BOM/尺寸表：数值汇总正确、导出文件能打开 —— 4 条
- 状态恢复：重启后项目与门状态不丢 —— 3 条
- 密钥与日志：日志不含 Key、不含成本价原文 —— 3 条

**第二层真实冒烟（会花钱，跑之前当场再问一次）**
1. 真实模型跑 1 次企划解析 + 3 方向（文本部分）；
2. 真实出图跑 **3 张**（每个方向 1 张），记录耗时与费用；
3. **产品经理拿 5–10 条真实企划样例打分**（覆盖要求 / 结构合规 / 风格可用 / 成本合理 / 语言质量），据此校准 D2、D3。

**第三层**：1440 / 390 宽度检查；导出文件用 Word/Excel 真打开一次。

## 十四、比赛官方需求逐条对齐（2026-09-21 产品经理给出原文）

官方要求原文：

> **鞋服智能设计 Agent**：实现业务需求解析、风格自主规划，可调用绘图工具、面料数据库、版型参数库，
> 快速完成鞋服款式生成、面料搭配、版型迭代，对接打样业务流程，辅助设计师开展创意构思、方案筛选、设计成果输出。

### 14.1 逐条对照

| # | 官方要求 | 我们的做法 | 状态 |
| --- | --- | --- | --- |
| 1 | **业务需求解析** | 企划文本 → 品类/风格关键词/目标人群/价格带/成本上限（缺项进 `missing`，不编） | ✅ 已在 2-1 范围 |
| 2 | **风格自主规划** | 由模型自主给出 3 个风格方向（名称/灵感/配色/廓形/出图提示词），不是模板填空 | ✅ 已在 2-2 范围（演示时要**展示规划理由**，体现"自主"） |
| 3 | **调用绘图工具** | 火山方舟 Seedream（已打通，真图验证：2K、20–30 秒/张） | ✅ **已跑通** |
| 4 | **面料数据库** | **示例库**（面料≈40 条，字段：克重/成分/价格区间/适用季节）；预留 `MaterialSource` 接口，可换企业真库 | ⚠️ 用示例库，**对外必须写明"示例库"** |
| 5 | **版型参数库** | **示例库**（版型≈8、工艺≈12、尺码≈4 套） | ⚠️ 同上 |
| 6 | **款式生成** | 按选定方向出款式效果图（每方向 1 张，可重试） | ✅ 已在 2-2 范围 |

| 8 | **版型迭代** | ❌ **当前范围只有"选版型"，没有"迭代"** | 🔴 **缺口（见 14.2 补强 1）** |
| 9 | **对接打样业务流程** | 仿真状态机（草稿→审批→已推送→打样中→评审）+ 预留对接位 | ⚠️ **是仿真不是真对接**，需按 14.2 补强 2 补齐"打样单"这一交付物 |
| 10 | 辅助**创意构思** | 3 个风格方向 + 灵感说明 | ✅ |
| 11 | 辅助**方案筛选** | 五道人工确认中的"选方向"；可并列比较 3 个方向 | ✅（演示时并排展示 3 张图 + 各自理由） |
| 12 | **设计成果输出** | 导出 Word 方案 + Excel（BOM/尺寸表）；PDF 暂缓 | ✅（PDF 看时间，可加） |

### 14.2 两处必须补强（都属"小改动、高性价比"）

**补强 1：版型迭代（官方明确写了"迭代"）**
- 做法：选定版型后，允许改 **2–3 个关键参数**（如裙长、腰围放松量、袖长）→ 代码重算尺寸表与用料估算 → 页面显示"改了什么、影响什么"→ **可选**重新出图（1 张）
- 为什么便宜：复用已有的版型库与尺寸表逻辑，不需要新模型能力；出图是可选动作（一次迭代约 1 张图，≤0.2 元）
- 验收：改参数后尺寸表数字确实变了，且标出"本次迭代第 N 版"

**补强 2：打样业务流程（"对接"要能看见）**
- 做法：生成一份**《打样单》**（Excel/Word，含款式图、面料、版型参数、尺寸表、工艺说明、备注），
  打样状态按状态机推进，并写明"**仿真流程，预留标准对接位**"
- 为什么这么做：真正的 PLM/ERP 对接需要对方的系统与授权（我们没有），
  但"**有打样单、有状态流转、有对接位**"足以在评审里说明"业务流程已被 Agent 串联"
- 对外口径（写死）：**"已对接打样业务流程（仿真演示 + 预留标准对接位）"**，不得说"已对接真实工厂系统"

### 14.3 对外演示口径（按官方要求逐条回应，照这个讲）

> 我们做了业务需求解析 → 风格自主规划（3 个方向，模型自己给理由）→ 调用绘图工具出真实效果图 →
> 从面料库/版型库取材 → 完成款式生成、面料搭配、**版型迭代**（可改参数重算尺寸）→
> 生成打样单并推进打样流程 → 最终输出 Word 方案与 Excel（BOM/尺寸表）。
> **其中面料库与版型库当前为仿真实例（界面明确标注"示例库"），架构上预留了接入企业真实库的完整门禁位。**

**三条不能说的话**：不能说"真实面料数据"、不能说"已对接真实工厂/PLM 系统"、不能说"真人实拍/AI 生成图是实物照片"。

## 十五、设计素材库与"参考图生成"（2026-09-21 实测结论 + 产品经理提议）

产品经理提议：**先搭数据库、在库里找参考图，再据此出图**。已实测验证并采纳，范围与口径如下。

### 15.1 实测结论：**方舟支持参考图输入**
- 调用 `/images/generations` 时传 `image` 字段（base64 data URI），**返回 200 并成功出图**
  （实测：以"写实模特正面图"为参考，生成"同一件衣服的背面视图"，产出 145 KB 图）。
- 意义：这解决了文生图**"同一件衣服多视角/多版本不一致"**的最大短板；
  也让"**先检索参考、再生成**"这条路走得通。

### 15.2 建"设计素材库"（与面料库/版型库并列，统一口径）

| 项 | 做法 |
| --- | --- |
| 表 | `design_asset`：图片路径、品类、风格标签、廓形、配色、面料、**来源**、生成参数、创建时间、是否可对外 |
| 来源（**三条红线**） | ① **我们自己生成的图**（可入库，能讲"Agent 参考历史设计，保持系列感"）② 合法购买的图库素材 ③ 公司自有设计稿/历史款图。**禁止**：爬电商/社交平台、用真实品牌在售爆款做仿款 |
| 检索（起步） | 标签 + 文本匹配（几百张足够）；**上千张或要"以图搜图"时**再引入向量检索（手册中 Chroma 为暂缓项，届时单独确认） |
| 出图流程 | `选方向 → 检索 1–2 张参考图 → 提示词 + 参考图一起送给模型 → 出图（记录用了哪张参考）` |
| 费用 | **不额外收费**（仍按张计费）；检索是本地免费 |
| 对外口径 | "**示例素材库 + 预留接入企业真实款式库的位置**"；不得宣称使用了品牌/电商真实图片 |

### 15.3 与比赛要求的关系
官方 12 条要求里没有直接写"参考图检索"，但它**加强第 2 条（风格自主规划）与第 8 条（版型迭代）**：
参考库能让"系列感"和"多视角一致"成立，是演示的加分项，不是必须项。
因此**优先级排在两条补强（版型迭代、打样单）之后**，但不砍——因为地基（能否传参考图）已验证可用，落地成本不高。
