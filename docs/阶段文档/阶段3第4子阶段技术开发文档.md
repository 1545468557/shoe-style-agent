# 阶段 3 · 第 4 子阶段 技术开发文档（版型改为 AI 生成 · 面料库外兜底生成）

**日期**：2026-09-21　**项目**：鞋服智能设计 Agent（款式工场）
**起因**：产品经理实测发现——输入「高跟鞋 / 羽绒服」，面料与版型仍返回连衣裙（因为**版型库 8 条全是连衣裙、面料库 40 条全是女装面料**，且推荐逻辑不看品类）。产品经理明确定调：

> **版型不用建库，让大模型自己生成（提示词注入）；面料从库里挑，挑不到就让它生成。**

---

## 一、本子阶段做什么

### ① 版型 = **模型生成**（不再从库挑，不建库）

- **输入给模型的上下文**（提示词注入）：企划解析结果（品类/风格/人群/价格带/补充说明）＋ 已选方向（名字/廓形/灵感）＋ 已选面料（名字/成分/克重）
- **模型输出的版型设计参数**（结构化 JSON）：

  | 字段 | 含义 |
  | --- | --- |
  | `name` | 版型名（如"连帽短款羽绒版型"） |
  | `silhouette` | 廓形（H/A/X/O…） |
  | `ease` | 关键松量：胸围/腰围/臀围/肩宽（cm，按品类给不同项） |
  | `structure_lines` | 分割线/省道/拼接（列表） |
  | `collar / sleeve / hem` | 领型 / 袖型 / 摆型 |
  | `length_cm` | 关键长度 |
  | `size_base` | 放码基准（基础码 + 档差说明） |
  | `reason` | 为什么这样设计（一句话） |
  | `category` | 品类（用于尺寸表计算） |

- **代码负责**：按生成参数 + 国标放码规则算出 **S/M/L/XL 尺寸表**；用料估算（面料克重/幅宽来自已选面料，库外则用模型给的需求参数）
- **任意品类都能用**：连衣裙、羽绒服、外套、裤装、**鞋类**（鞋则生成鞋型/楦型参数），不再硬塞连衣裙

### ② 面料 = **先查库，库外由模型生成规格建议**

- **库里能匹配**（现有逻辑）：从示例库候选中挑 3 条 + 给理由（provider = 模型名）
- **库里匹配不到该品类**（如羽绒服/高跟鞋）：模型**不给具体面料名**，而给 **面料需求规格建议**（如"防钻绒尼龙，克重 60–80g/m²，含充绒量建议"），并**明确标注**：

  > **AI 建议的面料规格（非真实物料；示例库未覆盖该品类，请补充企业物料库）**

- 界面同时给出「**去企业物料库补充**」的提示语（不新增功能，只是提示）

## 二、口径与红线（必须守）

| 现在会显示 | 改成 |
| --- | --- |
| 版型来自示例库（隐含"真实版型"） | **「AI 生成的版型设计参数（非工厂纸样 / 非打版文件）」**；基础版型如引用库则另标 |
| 面料来自示例库 | 库内：**示例数据 · 仿真实例**；库外：**AI 建议规格（非真实物料）** |
| — | **不做**可直接生产的纸样/CAD/DXF 导出；只给**设计参数 + 结构说明 + 尺寸表** |

## 三、接口与数据（不新增费用型副作用）

| 接口 | 说明 |
| --- | --- |
| `POST /api/project/{id}/pattern-design` | **生成版型设计参数**（一次文本模型调用，约 ¥0.01），落库到新表 `pattern_design`（新建表，不改老表结构） |
| `GET /api/project/{id}/pattern-design` | 读取已生成的版型设计（**不调用模型、零费用**），用于刷新后回显与「我的设计」查看 |
| `GET /api/project/{id}/materials` | 保留；**新增库外分支**：无候选时返回模型生成的面料规格建议，`provider = "model-generated"` |

> 原「版型库推荐」逻辑保留但**不再作为主路径**（仅在无法调用模型时兜底，并如实标注 `tag-fallback`）。

## 四、前端改动

1. 版型区：按钮改为 **「AI 设计版型」** → 展示生成参数（廓形/松量/分割线/领袖摆/长度/放码基准/理由）+ 一行口径标注 → **「采纳这个版型，下一步」**（门 4 不变）
2. 面料区：库外时显示「AI 建议的面料规格」卡片（标注"非真实物料"），样式与库内卡片区分（虚线框）
3. 尺寸表：由代码按生成参数计算（S/M/L/XL）

## 五、本子阶段**不**做

- 不建版型库（按产品经理定调）
- 不做 CAD/纸样/DXF/PLM 对接
- 不做鞋楦库、鞋材库（鞋类只生成设计参数与规格建议，标注为 AI 生成）
- 不动五道人工确认的门逻辑

## 六、测试与验收（mock，不花模型钱）

| --- | --- |
