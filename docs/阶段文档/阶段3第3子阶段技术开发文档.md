# 阶段 3 · 第 3 子阶段 技术开发文档（顶栏三个入口）

**日期**：2026-09-21　**项目**：鞋服智能设计 Agent（款式工场）

## 一、先回答产品经理的问题

**「我的设计」＝历史记录**：每做一个方案都会存进本地数据库（现在就有几十条），只是**没有页面可以看**。
所以做这个入口前必须先改一个行为：**现在一打开页面就自动建一个空方案**，导致历史里全是"新方案"空壳 → 本子阶段把"建方案"改成**你点「新建」或第一次点「开始理解」时才建**。

## 二、三个入口分别做成什么

| 入口 | 内容 | 说明 |
| --- | --- | --- |
| **我的设计** | **方案列表**：缩略图（方向图，3:4）、方案名、**当前进度**（企划✓/方向✓/面料…/打样✓）、最近更新时间、"继续做"按钮 | 点「继续做」→ 工作台载入该方案（门状态、已有内容全部回显） |
| **素材库** | **示例库浏览**（只读）：面料 40 条（成分/克重/价格区间/手感/季节标签）、辅料 6、版型 8（松量/可选裙长/难度）、工艺 12、尺码 4。每条都标 **示例数据 · 仿真实例** | 让评委看到"库"是真存在的（不是现编的） |
| **设置** | 只读展示：**AI：DeepSeek**（文本）、**出图：火山方舟 doubao-seedream-5-0-lite（2K）**、示例库条数、口径声明（示例数据/非实物照片/估算值/演示流程） | **不显示任何密钥**；不提供修改入口 |

## 三、接口（新增 2 个，都不花钱）

### `GET /api/projects`
```json
{"items":[{"id":71,"name":"夏季度假连衣裙","status":"sampling_approved","updated_at":"2026-09-21 17:59:29",
           "progress":{"brief":true,"direction":true,"material":true,"pattern":true,"sampling":true},
           "thumbnail":"/assets/71/direction_1.png","gate_count":5,"gate_total":5}]}
```
- 默认按 `updated_at` 倒序，`limit` 默认 30；**含空方案过滤**（没有任何内容的空方案不返回，避免历史被空壳塞满）

### `GET /api/library`
```json
{"materials":[...],"trims":[...],"patterns":[...],"crafts":[...],"sizes":[...],"is_sample":true}
```
- 直接返回示例库内容，**全部带 `is_sample: true`**

## 四、行为改动（重要）

1. **不再进页面就建方案**：打开工作台＝"新建"状态（不落库）；点 **「开始理解」**（或顶栏「新建设计」）时才真正创建。
2. **「继续做」载入历史方案**：工作台支持"带方案 id 打开"，进入后直接显示该方案当前进度（该到哪一步就到哪一步）。
3. 顶栏三个入口变成**可切换的页面**；工作台仍是默认页。切换不丢当前方案。

## 五、本子阶段**不**做

- 账号体系、登录（按 D11 砍除）
- 重命名 / 删除 / 复制方案（先不做，避免误删数据；如需要下个子阶段再加**软删除**）
- 素材库的增删改（只读浏览）
- 不做真实数据接入（仍是示例库）

## 八、给产品经理的三个确认点

1. **做什么/不做什么**：我的设计（历史列表+继续做）、素材库（只读浏览）、设置（只读展示）；**不做**账号、不做重命名/删除、不做素材库编辑
2. **有没有新增费用/外部平台/数据上传**：**都没有**
3. **会不会影响验收**：不影响五道门；改动"进页面就建方案"的旧行为（**这是修 bug，不是删功能**——原来会让历史记录被空方案污染）
