## 二、要改成什么

| 编号 | 改成 |
| --- | --- |
| F1 | **导出（Excel + Word）尺寸表按品类生成**：部位名取 `size_spec.labels`，单位取 `size_spec.unit`；鞋类输出 鞋码/脚长/跖围/鞋帮高（靴类=筒高），服装输出 胸围/腰围/臀围/衣长（+袖长）。**不再出现"裙长"** |
| F2 | **导出（Excel + Word）输出多档表**：鞋 225/230/235/240/245（档差 5mm）；服装 S/M/L/XL（档差 4cm），取自 `size_spec.tiers` |
| F3 | **修 Word 导出 500**：AI 面料 → 从 `MaterialSuggestion` 取名称/成分/价格区间；AI 版型 → 从 `PatternDesign.payload` 取；示例库条目仍走库；**任何情况都不 500**，最差用 `note` 兜底并在文中标注"AI 生成建议" |
| F4 | **用料清单"版型"行按品类写**：鞋类→`跖围 220mm / 鞋帮高 …`；靴类→`筒高 …`；服装→`腰围松量 …cm`。金额为 0 的行显示「不计入成本」，不再显示"0~0 元" |
| F5 | **品类判断不再依赖 bom**：前端用 `st.brief.parsed.category` 与版型 payload 的 category 本地判断（含 鞋/靴/跟/凉/拖 → 鞋类；含"靴"→ 靴类），bom 有 `unit` 时以 `unit` 为准。未算料时也显示「跖围调整 / 鞋帮高调整」 |
| F6 | **尺寸表去重 + 修正档差**：鞋码与脚长不再同值重复；跖围档差由 0.4 改为 **每码 +4mm**（225↔245 共 ±8mm），并在注释标"估算值" |
| F7 | **凉鞋/拖鞋不输出"筒高/鞋帮高"**：只有靴类输出「筒高」（取版型显式参数，没有就写"未给出"），其余鞋型不硬造该行 |
| F8 | **前端尺寸表改为按后端 `labels` 的键集合渲染**（不再固定 4 行），并展示 `tiers` 多档；缺哪一行就不渲染哪一行 |
| F9 | **辅料改为 AI 按品类生成**（与面料/工艺同一条路）：新增表 `trim_suggestion`；鞋类→内里/鞋垫/鞋带或魔术贴/大底/中底/五金扣件/防滑贴；服装→里布/拉链/纽扣/衬布/松紧/织带。**提示词硬约束禁止跨品类**；用料清单改读采纳的 AI 辅料 + AI 价格区间，全部标「AI 估算值，非采购报价」 |
| F10 | **重启后端**使最新代码生效（当前进程比最后一次提交早 10 分钟）；启动脚本增加"代码比进程新则提示重启"的说明 |

## 三、接口与数据

| 接口 | 说明 |
| --- | --- |
| `GET /api/project/{id}/bom`、`POST /api/project/{id}/bom` | 返回值新增 `size_spec.tiers`（多档）；`bom.items` 的「版型」行 qty 改为品类文案；辅料行来自 AI 辅料 |
| `POST /api/project/{id}/trims/generate` | AI 生成 3–5 条**本品类**辅料建议（一次文本调用，约 ¥0.005–0.01），落库 `trim_suggestion` |
| `GET /api/project/{id}/trims/generate` | 读取已生成辅料建议（零费用，刷新回显） |
| `POST /api/project/{id}/trims/accept` | 采纳选中的辅料（传编号列表） |
| `POST /api/project/{id}/export` | 修 500；Excel 尺寸表 = 多档 + 品类部位名 + 正确单位（mm/cm） |

- 新表 `trim_suggestion` 用 `create_all` 新建，**不改动老表结构**；示例库辅料（`seed/trims.json`）保留为"素材库参考页"的内容，**不再参与生成**。
- 前端在「面料」步骤后、或「用料与尺寸」步骤内新增「辅料建议（AI 生成）」卡片，可勾选采纳。
