# 鞋服智能设计 Agent（款式工场）· 视觉设计要求单

> 给**外部设计师**用的一页纸。产品是给**服装设计师/主理人**用的 AI 设计工作台：
> 输入企划 → AI 出 3 个风格方向（效果图）→ 选一个 → 配面料与版型 → 算出用料与尺寸 → 生成打样单。
> 交付场景：**比赛现场演示 + 评委用手机看**。要"一眼像个高级的时尚设计工具"，不是企业后台。

## 一、要交付什么（必须）

1. **5 个页面的视觉稿**（可以是 Figma 文件，或 5 张 PNG，1440 宽 + 390 宽各一套）
2. **设计规范**：色板（HEX）、字体（中文/英文/数字分别用什么、字号层级 6 级）、间距规则（建议 8 的倍数）、圆角与描边规则、图片比例
3. **组件样式**：主/次按钮、输入框、卡片、数字展示、状态徽标、标签、图片占位

## 二、5 个页面（每页的用途与必须显示的字段）

| 页 | 用途 | 必须显示 |
| --- | --- | --- |
| ① 我的设计 | 方案列表（工作台首页） | 缩略图（3:4）、方案名、状态（待定面料/待审批/已完成） |
| ② 输入企划 | 用户写一段话描述要做什么衣服 | 大输入框、解析结果（品类/风格/人群/价格带）、"未提供"提示 |
| ③ 挑一个方向 | 3 张效果图并排挑 | 3:4 大图、方向名、一句灵感说明、"就用这个方向"、可勾选两个做并排对比 |
| ④ 定面料与版型 | 从面料库挑 + 定版型与工艺 | 面料名/成分/克重/价格区间/**AI 搭配理由**；版型参数（腰围松量、可选裙长）；可多选工艺 |
| ⑤ 用料与导出 | 成本与尺寸表 + 导出 | 用料清单、**成本合计（醒目）**、尺寸表、导出 Word/Excel、打样进度 |

## 三、不能改的（产品口径，红线）

1. 页面上必须能看见"**示例数据 · 仿真实例**"字样（数据是仿真的）
2. 效果图旁必须标注"**AI 生成示意图（非实物照片）**"
3. 成本必须标"**估算值**"；打样必须标"**演示流程**"
4. 界面**不出现**内部术语：不写"门1/门2""BOM""迭代器"这类词；按钮说人话（"就用这个方向"而不是"确认样本"）
5. **不要**设计成聊天对话框样式（这是工作台，不是聊天机器人）

## 四、视觉方向（可任选其一，或组合）

| 方向 | 参考 | 一句话 |
| --- | --- | --- |
| A 暗色沉浸 | Midjourney / Runway / Krea | 黑底 + 大图发光，效果图像在展台上 |
| B 精致极简 | Linear / Vercel / Figma | 白底但细节极讲究，字重层次与微阴影 |
| C 时装品牌感 | SSENSE / COS / Nike SNKRS | 超大图 + 超大标题 + 横向滑动，冲击力强 |

**我们倾向 C**（这是给人看图的行业），但**以设计师判断为准**。

## 五、技术与协作约束

- 实现栈：**Next.js + React + 纯 CSS**（可直接改成 Tailwind class）；**不引入重型 UI 框架**
- 图片比例：效果图统一 **3:4**（竖版）；方案缩略图也 3:4
- 移动端：390 宽要能用（评委多半拿手机看）；横向滑动/单列自适应
- 无障碍：交互元素可键盘访问、对比度足够
- 交付格式：Figma 链接（推荐）或 PNG + 一份说明；**不需要写代码**

## 六、时间与验收

- 期望：**1 天内**给第一版（5 页中的前 3 页也行，先看气质）
- 验收：我们把视觉稿实现出来给你看一眼，**风格由产品经理确认**
- 我们提供：现有可运行版本地址（含真实数据与真实 AI 出图），设计师可对照
